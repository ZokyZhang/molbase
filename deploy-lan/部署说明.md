# MolBase 知识库局域网化部署 + Skill/MCP 导入说明

> 把本地知识库（MolBase）做成「Skill + MCP 工具」双通道，服务器部署在局域网虚拟机，供所有设备共用并导入 WorkBuddy 使用。

---

## 一、架构总览

```
局域网各设备（手机 / 平板 / 其他电脑）
   └─ WorkBuddy（每台设备）
        ├─ Skill「molbase」      —— 协议与约束指引（大脑）
        └─ MCP 工具「molbase」    —— 实际操作（手），stdio 本地进程
             └─ HTTP 转发 → http://10.0.0.200:8787（中心知识库服务器，虚拟机）
```

| 组件 | 位置 | 作用 |
|---|---|---|
| 中心服务器 | 虚拟机 `10.0.0.200`，端口 `8787` | 监听 `0.0.0.0`，唯一常驻服务，所有设备共用同一份知识库 |
| MCP 工具 | 每台设备本地（stdio 进程） | 零依赖单文件，把 HTTP API 翻译成 MCP 工具 |
| Skill | 每台设备 `~/.workbuddy/skills/molbase/` | 告诉模型何时查、何时存、约束与协议 |

---

## 二、交付物清单

| 文件 | 用途 |
|---|---|
| `molbase_mcp.py` | MCP Server（单文件，零依赖 stdio，纯标准库） |
| `deploy-lan/start-server.sh` | 虚拟机一键启动脚本（`0.0.0.0:8787`） |
| `deploy-lan/molbase-lan.service` | systemd 常驻服务单元（可选） |
| `deploy-lan/mcp.json.example` | WorkBuddy MCP 配置示例 |
| `~/.workbuddy/skills/molbase/SKILL.md` | Skill 协议文档（已增强） |
| `deploy-lan/部署说明.md` | 本文档 |

## 三、第一步：部署到虚拟机（迁移 + 启动）

### 3.1 迁移知识库到虚拟机

开发机整个 `molbase/` 项目（含 688 条知识的 `data/molbase.db`、`knowledge_repo/`、`skills_repo/`、`molbase/` 包、`deploy-lan/`）同步到虚拟机 `/home/zoky/molbase/`：

```bash
# 在开发机执行（paramiko 已可用，或改用 scp）
scp -r /c/Users/Administrator/WorkBuddy/2026-11-17-22-17-16/molbase \
    zoky@10.0.0.200:/home/zoky/
```

> 数据目录 `data/`、`knowledge_repo/`、`skills_repo/` 一并迁移，保证虚拟机与开发机知识库完全一致。
> 增量同步可只传 `data/molbase.db`。

### 3.2 启动局域网服务

```bash
ssh zoky@10.0.0.200
bash /home/zoky/molbase/deploy-lan/start-server.sh     # 前台启动（0.0.0.0:8787）
```

**常驻推荐（systemd，开机自启 + 崩溃自愈）：**

```bash
sudo cp /home/zoky/molbase/deploy-lan/molbase-lan.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now molbase-lan
sudo systemctl status molbase-lan
```

### 3.3 验证

```bash
# 在任意设备执行，应返回 {"status":"ok","stats":{...}}
curl -s http://10.0.0.200:8787/health
```

## 四、第二步：各设备导入 WorkBuddy

### 4.1 导入 Skill

把 `molbase` 技能目录放到设备用户级技能目录：

```bash
mkdir -p ~/.workbuddy/skills/molbase
# 拷贝 SKILL.md 到该目录（Windows：C:\Users\<用户>\.workbuddy\skills\molbase\SKILL.md）
```

WorkBuddy 重启后会自动识别 `molbase` 技能。

### 4.2 导入 MCP 工具

编辑 `~/.workbuddy/mcp.json`（Windows：`C:\Users\<用户>\.workbuddy\mcp.json`），加入：

```json
{
  "mcpServers": {
    "molbase": {
      "command": "python",
      "args": ["<本机绝对路径>/molbase_mcp.py"],
      "env": { "MOLBASE_URL": "http://10.0.0.200:8787" }
    }
  }
}
```

> - `args` 里的路径换成该设备上 `molbase_mcp.py` 的实际绝对路径（单文件可随意放置）。
> - `MOLBASE_URL` 统一指向中心服务器 `10.0.0.200:8787`。
> - 配置后需在 WorkBuddy 连接器管理页对新增的 `molbase` 点「信任」才生效。

## 五、使用验证

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 探活 | MCP 调用 `molbase_health` | 返回 `status: ok` + 688 条知识统计 |
| 2 检索 | MCP 调用 `molbase_query`（query="虚拟机 环境"） | 返回最小上下文块，含 `10.0.0.200` 相关条目 |
| 3 沉淀 | MCP 调用 `molbase_ingest_knowledge` | 返回 `state`（duplicate/conflict/merge） |
| 4 收尾 | MCP 调用 `molbase_harvest` | 返回 `entry_id` 与 `engine` |

## 六、回滚方案

| 操作 | 回滚 |
|---|---|
| 虚拟机服务 | `sudo systemctl stop molbase-lan`（或 Ctrl+C）即可，数据落盘不丢 |
| 迁移 | 虚拟机删除 `/home/zoky/molbase/`，开发机 `127.0.0.1:8787` 仍可本地运行 |
| MCP 导入 | 从 `mcp.json` 移除 `molbase` 段即可 |
| Skill 导入 | 删除 `~/.workbuddy/skills/molbase/` 目录 |

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| MCP 工具调用报「无法连接」 | 中心服务器未启动或 IP 变 | `curl http://10.0.0.200:8787/health` 探活；核对虚拟机 IP（桥接 DHCP 可能变化，建议路由器 MAC 静态绑定） |
| `python` 命令找不到 | 设备未装 Python | MCP 用 stdio 需 Python 3；或改用 HTTP 远程调用方案 |
| 端口 8787 不通 | 虚拟机防火墙 | `sudo ufw allow 8787/tcp` 或关闭 ufw |
| 知识库内容不一致 | 只迁了部分目录 | 确认 `data/ knowledge_repo/ skills_repo/` 全部迁移 |
