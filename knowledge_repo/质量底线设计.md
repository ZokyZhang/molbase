# MolBase 质量底线设计（四道防线 + 两道闸门）

> 日期：2026-11-18 ｜ 范围：`molbase/orchestrator.py` + `molbase/server.py` + `molbase/store` + `molbase/sanitize.py` + `molbase/config.py`
> 验证：`python -m unittest tests.test_molbase` → **59/59 全绿**（新增 7 个质量底线用例）

---

## 一、结论先行

MolBase 的定位是「给其他系统/agent 当底座的代工中间层」，所以它的质量底线不是「答得多好」，而是**「答错/存错的代价有多低、可不可控」**。核心原则一句话：

> **宁可不答，不可错答；宁可少存，不可错存。**

落成「四道防线 + 两道闸门」：

| 防线 | 管什么 | 闸门 | 状态 |
|---|---|---|---|
| ① 检索输出端 | 防止**错答** | **abstain 闸门**（confidence + 强制溯源） | ✅ 已落地 |
| ② 写入输入端 | 防止**错存** | **冲突闸门**（pinned/duplicate/conflict/merge） | ✅ 已落地 |
| ③ 运行兜底 | 防止**崩/漏** | 零模型降级（已有）+ PII 脱敏 | ✅ 脱敏新增 |
| ④ 进化侧 | 防止**越学越坏** | reject 隔离 + 死知识归档 | ✅ 已落地 |

---

## 二、第一道防线：检索输出端（abstain 闸门）

### 2.1 问题

改造前 `/query` 只要有命中就返回，没有「这条命中的可信度有多高」的信号，低相关内容也会被硬塞给调用方，等于把幻觉风险传导给下游。

### 2.2 设计

给 `/query` 返回值加两个字段：

- **`confidence`**（0~1）：综合置信度，两因子加权（零模型、确定性、可解释）：

  ```
  confidence = 0.70 × 匹配强度 + 0.30 × 唯一性 margin
  ```

  - `匹配强度`：top1 的 **BM25 原始得分**（未归一化）相对 `WEB_SEARCH_TRIGGER_SCORE` 的倍数（封顶 1.0）——用原始分而非归一化分，因为归一化会把弱命中也拉到接近 1，无法反映真实匹配强弱；
  - `唯一性 margin`：top1 与 top2 原始分差占 top1 的比例（越大越唯一，单命中时为 0）。

- **`abstain`**（bool）：`confidence < ABSTAIN_CONFIDENCE(0.45)` 时为 `true`，表示「宁可不答也不错答」。调用方据此明确说「不知道」，而不是硬答。

### 2.3 溯源强制

`QueryResult` 本就强约束 `entry_id + title + source + content` 三元组（dataclass 必填），非 abstain 的答案天然带来源，可直接核对。

## 三、第二道防线：写入输入端（冲突闸门）

### 3.1 问题

SimHash 只能挡「几乎一模一样」的重复，挡不住「同一事实、不同来源、说法矛盾」。家庭多源场景（爸爸记账 vs 妈妈记账）迟早撞上。

### 3.2 四态判定（按优先级早命中早返回）

| 状态 | 触发条件 | 动作 |
|---|---|---|
| **pinned** | 已有条目 `meta.pinned=true` | 拒绝覆盖 |
| **conflict** | 同 ID 且 `source` 不同 | 不覆盖，写入 `conflicts` 表待裁决 |
| **duplicate** | 同 ID 同源且内容近重复（SimHash 或 `SequenceMatcher ≥ 0.85`） | 跳过写入 |
| **merge / new** | 同源更新 / 全新 | 正常 upsert |

**关键设计取舍**：`conflict` 优先于 `duplicate`。因为「爸爸记五千 vs 妈妈记八千」文本高度相似，会被 SimHash 误判为重复，但它本质是矛盾——所以「来源不同」这一信号优先级更高。

### 3.3 来源标注与幂等

- `source` 字段全程保留（`Entry.source`），冲突判定依赖它；
- `entry_id` 为 `PRIMARY KEY`，`upsert` 走 `ON CONFLICT DO UPDATE`，天然幂等。

## 四、第三道防线：运行兜底（PII 脱敏）

- 已有「零模型自足 + 模型失效自动降级、绝不崩溃」是领先优势，本层只补 PII 脱敏。
- 新增 `molbase/sanitize.py`，纯标准库 `re`，输出前对命中内容打码：

| 类型 | 示例 | 打码后 |
|---|---|---|
| 手机号 | 13800138000 | 138\*\*\*\*8000 |
| 邮箱 | test@example.com | t\*\*\*@example.com |
| 身份证 | 110101199001011234 | 110\*\*\*\*\*\*\*\*\*\*\*1234 |
| 银行卡 | 6222021234567890 | \*\*\*\*\*\*\*\*\*\*\*\*7890 |
| 密码/token | password=abc123 | password=\*\*\* |

由 `SANITIZE_ENABLED=True` 总开关控制，在 `server._result_to_dict` 输出前生效。

## 五、第四道防线：进化侧（越学越好的刹车）

| 机制 | 实现 | 参数 |
|---|---|---|
| 负反馈隔离 | `reject` 累计达阈值 → `meta.quarantined=true`，`_rebuild` 过滤，不参与召回 | `QUARANTINE_REJECT_THRESHOLD=3` |
| 死知识归档 | 长期未访问且「已隔离或热度 ≤ 0」→ `meta.archived=true`，保留在库可恢复 | `ARCHIVE_DAYS=180`、`ARCHIVE_HEAT_MAX=0.0` |

隔离与归档条目都**保留在库**（不物理删除），清除对应 meta 标志即可人工恢复。

---

## 六、参数配置（全部硬编码于 `config.py`）

| 参数 | 默认值 | 作用 |
|---|---|---|
| `ABSTAIN_CONFIDENCE` | 0.45 | abstain 置信度阈值 |
| `CONFLICT_DUPLICATE_SIM` | 0.85 | duplicate 相似度阈值 |
| `SANITIZE_ENABLED` | True | PII 脱敏开关 |
| `QUARANTINE_REJECT_THRESHOLD` | 3 | reject 隔离阈值 |
| `ARCHIVE_DAYS` | 180.0 | 死知识归档天数 |
| `ARCHIVE_HEAT_MAX` | 0.0 | 归档热度上限 |

## 九、风险识别与回滚

| 风险 | 影响 | 缓解/回滚 |
|---|---|---|
| `abstain` 阈值 0.45 过严/过松 | 误拒绝或误答 | 调 `ABSTAIN_CONFIDENCE`；观测 abstain 率微调 |
| `conflict` 规则过保守（来源不同即判矛盾） | 同 ID 迁移源被误判 | 缺来源时不判冲突；同源仍走 merge |
| 隔离/归档误伤正常条目 | 条目不可召回 | 仅打 meta 标志，不物理删除，清除标志即恢复 |
| 生产库已有旧数据无 conflict 状态 | 首次升级无历史冲突 | `conflicts` 表空表自建，不迁移旧数据 |
